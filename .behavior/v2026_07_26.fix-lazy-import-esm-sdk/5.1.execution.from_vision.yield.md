## the change

`src/domain.operations/repls/genBrainRepl.ts`:
- removed the eager top-level `import { query } from '@anthropic-ai/claude-agent-sdk'`
- added `importEsm = new Function('specifier', 'return import(specifier)')` — a native
  dynamic import that tsc cannot downlevel to `require()` under `module: commonjs`
- added `getClaudeAgentSdk()` which imports via
  `pathToFileURL(require.resolve('@anthropic-ai/claude-agent-sdk')).href` (module-anchored)
- `extractResultFromQuery` param typed as `Query` (type-only import, erased at build)
- `invokeQuery` now does `const { query } = await getClaudeAgentSdk()` at point of use
- jest is detected via the injected `jest` global, NOT `process.env.JEST_WORKER_ID`.
  the env var leaks into any child process a jest run spawns (e.g. a commonjs consumer's
  `rhx` subprocess), which would then wrongly take the require() branch and throw
  ERR_REQUIRE_ESM — the very bug this fix removes. the `jest` global is scoped to the
  jest sandbox and does not cross a process boundary, so a spawned subprocess correctly
  uses the native import. (surfaced by the peer-review round; see below.)

`src/contract/sdk/commonjsLoadability.acceptance.test.ts` (new):
- child-process commonjs `require()` of built `dist` under `--no-experimental-require-module`
  (reproduces the consumer's no-`require(esm)` env so the eager-import regression bites)
- asserts registry populates (3 atoms / 4 repls) with no throw
- static-inspects the emitted repl module: retains `import(`, no eager sdk `require()`

`.depcheckrc.yml`:
- added the 5 role/brain packages the pre-existing rhachet upgrade added to package.json
  (`rhachet-brains-fireworksai`, `rhachet-brains-xai`, `rhachet-roles-bhrowser`,

l3 (enrollment) surfaced the sharpest finding — the **`JEST_WORKER_ID` leak**. the env-var

the env var. `case3` now inherits `JEST_WORKER_ID` yet still uses the native import and the
real `ask` returns — the definitive proof the leak cannot break a commonjs consumer.

## the jest-trap CI tripwire (r10 i006 top nitpick → closed)

r10's top-ranked leftover nitpick was that the `typeof jest` compile-dependency had no CI
tripwire — a future `tsconfig "types": ["node"]` would silently drop the `@types/jest`
ambient and reopen the outage. addressed two ways: (1) the accepted-risk `.note` in the
loader (the reviewer's own offered alternative), and (2) a real guard —
`genBrainRepl.jestGlobalCompileGuard.integration.test.ts` — that fails loud if
`tsconfig.json` restricts `compilerOptions.types` without `jest` present. green (2/2).

## the loader extraction (r11 i007 → the headline convergence)

r11 converged 4 rounds of feedback into one coherent extraction; i did it. the generic esm
loader moved out of the domain file into `src/infra/esm/`:

- **`importEsmSafe.ts`** — a generic `importEsmSafe<T>({ specifier, jestFallback })` that owns
  the `new Function` native-import wrapper, the jest-vs-native branch (now with an injectable
  `jestFallback` seam), the module-anchored package lookup, and the loud error wrap.
  `genBrainRepl.ts` reduces to a one-line call. this closes the decompose-for-recompose item
  raised since i002.
- **`asEsmLoadHelpfulError.ts`** (renamed from `asSdkLoadHelpfulError`) — now takes
  `{ error, specifier, branch }`, so the hint is branch-accurate (a jest require() failure no
  longer advises "native dynamic import()") and the shaper is genuinely reusable, not just
  positioned for reuse.
- **unit seam** — `importEsmSafe.test.ts` + `asEsmLoadHelpfulError.test.ts` exercise both the
  fallback path and the branch-threaded error under jest, without a spawn (the seam item 1
  enables).
- **acceptance rewire** — `case2` inspects the built `importEsmSafe.js` for the native
  `import(`; `case2b` keeps the no-eager-require guard on `genBrainRepl.js`; ask/act native
  proofs unchanged.
